# 知识图谱字段说明

## 通用实体

| JSON 字段 | Excel 常用字段 | 类型 | 说明 |
|---|---|---|---|
| `key` | `entity_key` | String | 稳定且唯一的项目实体编号 |
| `type` | `entity_type` | String | 实体类型 |
| `name` | `name` | String | 简体或规范名称 |
| `trad` | `name_traditional` | String | 繁体名称 |
| `aliases` | `aliases` | Array[String] | 别名、异名；无值时为空数组 |
| `category` | `category` | String | 专题或上级分类 |
| `period_start` | `period_start` | String/Number | 起始年代 |
| `period_end` | `period_end` | String/Number | 终止年代 |
| `description` | `description` | String | 现代整理说明 |
| `location` | `location_text` | String | 历史位置描述 |
| `source_key` | `source_key` | String | 来源编号 |
| `evidence_ids` | `chunk_key` | Array[String] | 支撑该实体的史料片段编号 |
| `quote` | `description_quote` | String | 直接证据引文 |
| `review_status` | `review_status` | String | 转换为 `published` 或 `draft` |
| `confidence` | `confidence` | Number | 数据置信度 |
| `grid_x/grid_y` | `项目坐标` | Number | Godot 逻辑网格坐标 |

## 通用关系

| JSON 字段 | Excel 字段 | 类型 | 说明 |
|---|---|---|---|
| `key` | `relation_key` | String | 关系记录编号 |
| `source_id` | `source_key` | String | 起点实体编号，不是文献来源编号 |
| `predicate` | `relation_type` | String | 机器可读关系类型，如 `PART_OF` |
| `label` | `relation_label` | String | 面向用户的中文关系名 |
| `target_id` | `target_key` | String | 终点实体编号 |
| `evidence_ids` | `chunk_key` | Array[String] | 关系证据片段编号 |
| `evidence_quote` | `evidence_quote` | String | 关系证据引文 |
| `evidence_type` | `evidence_type` | String | 史料记载、推导结论等 |
| `review_status` | `review_status` | String | 审核状态 |

## 地图点位

`changan_points.json` 是完整实体集的地图投影，仅包含具有有效项目坐标且属于地点类的实体。

| 字段 | 类型 | 说明 |
|---|---|---|
| `key` | String | 与完整实体一致的 ID |
| `zone` | String | 地图分区；初版来自实体 `category`，需人工复核 |
| `grid_x/grid_y` | Number | Godot 网格坐标，不是屏幕像素 |
| `name/trad/type/aliases` | Mixed | 展示信息 |
| `description/location` | String | 本地降级展示内容 |
| `source_ids/evidence_ids` | Array[String] | RAG 和引用溯源 |

> `zone` 是现阶段沿用原表 `category` 的游戏兼容字段。由于原表分类仍在修订，本 PR 不对其取值做归一化；原始分类信息以 `category` 和 `properties` 为准。

## 历史时间轴

`history_timeline.json` 是完整 `HistoricalEvent` 实体的游戏兼容视图。它保留大事记表原始字段，并额外提供当前 Godot 时间轴所需字段。

| JSON 字段 | Excel 字段 | 类型 | 说明 |
|---|---|---|---|
| `key` | `timeline_key` | String | 历史事件实体的稳定编号 |
| `type` | — | String | 固定为 `HistoricalEvent` |
| `id` | `timeline_key` | String | 兼容当前游戏读取逻辑，与 `key` 相同 |
| `year` | `year_ce` | Number | 游戏排序和筛选使用的公元年份 |
| `title` | `event_name` | String | 游戏时间轴标题 |
| `desc` | `summary` | String | 游戏时间轴摘要 |
| `date_display` | `date_display` | String | 面向用户展示的历史日期 |
| `dynasty/reign_title` | 同名字段 | String | 朝代和年号 |
| `event_type` | `event_type` | String | 事件分类 |
| `historical_significance` | 同名字段 | String | 历史意义 |
| `changan_impact` | 同名字段 | String | 对长安城的影响 |
| `related_entity_keys` | 同名字段 | Array[String] | 原表关联实体编号 |
| `related_point_ids` | `related_entity_keys` | Array[String] | 兼容游戏的关联点位编号 |
| `source_key/source_ids` | `source_key` | String / Array[String] | 来源编号及其数组形式 |
| `chunk_key/evidence_ids` | `chunk_key` | String / Array[String] | 史料片段编号及其数组形式 |
| `review_status` | `review_status` | String | 审核状态 |

## 研究结论

`research_claims.json` 完整保留联合总表“研究结论表”的 18 个字段。未填写的单元格输出为 `null`，不推测或补写原表没有的内容。

| 字段 | 类型 | 说明 |
|---|---|---|
| `claim_key` | String | 研究结论稳定且唯一的编号 |
| `claim_title` | String | 结论标题 |
| `claim_text` | String | 完整研究结论 |
| `popular_text` | String/null | 面向公众的简化表述 |
| `claim_type` | String | 结论类型 |
| `subject_keys` | String/null | 结论涉及的实体编号，保留原表写法 |
| `subject_relation_type` | String/null | 涉及的关系类型 |
| `proposed_by` | String/null | 提出者 |
| `source_key` | String/null | 资料来源编号 |
| `chunk_key` | String/null | 证据片段编号 |
| `basis_text` | String/null | 依据说明 |
| `reasoning_chain` | String/null | 推理过程 |
| `scope` | String/null | 适用范围 |
| `limitations` | String/null | 限制条件 |
| `claim_status` | String/null | 结论状态 |
| `confidence` | Number/String/null | 原表置信度 |
| `review_status` | String | 审核状态 |
| `note` | String/null | 备注 |

## 空值与引用规则

- 多值字段统一输出数组，不用逗号拼接字符串。
- 未知文本字段可以省略；不得用“无”“待补”伪装成有效数据。
- ID 创建后不得因名称修改而改变。
- 所有关系端点必须存在于实体表。
- 所有证据编号必须存在于史料片段表。
- Excel 中的项目坐标与 Godot 屏幕像素坐标含义不同，最终位置必须在游戏中抽查。
- 游戏兼容字段由导出脚本生成；除人工验收修订外，不直接编辑生成文件来修正原始数据。
