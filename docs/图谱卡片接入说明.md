# 知识卡片与 RAG 接入说明

## 最终界面

- 远景使用 V3 名称与尺度卡片，位置保持右上角。选中的坊、道路高亮；朱雀门街高亮不穿过皇宫。中近景不绘制高亮。
- 中近景卡片分为概述、详细信息、空间图谱、推理问答四页，分页按钮为同款字体、16号。点击卡片非交互区域按 1→2→3→4→1 循环。
- 概述页沿用原卡片，地图动态尺寸显示米，保留数值；不改变史料原文单位。
- 详细信息页读取 `data/generated/entities.json`。保留原圆圈、字体字号与字段分隔线；圈上显示实体名称，圈内保留实体类型。字段区可滚动，空值隐藏，关联编号解析为名称，不展示补充说明。
- 坊字段：所属区域、存在时期、主要功能、次要功能、功能依据、邻近道路、邻近水渠。
- 道路字段：道路等级、道路类型、走向、位置范围、起点、终点、原文路宽、换算路宽、换算依据、连接城门、沿线坊区、功能说明。
- 空间图谱页恢复原九宫格邻坊图，选中坊固定居中；道路名称横排或竖排。边缘绘制灰色外郭城墙，城外留空，道路在墙处截止。该图来自地图网格，不能描述为多跳推理结果。
- 推理问答页上方 AI 问答、下方公开史料证据；两个问题按钮上下排列、直接发送。每轮生成两个相关新问题并同步到正文和按钮。问题最多20字，整条回答含推荐问题最多300字，超限时显示前截断；不自动滚到底部，不显示信息范围或重新查询按钮。
- 图鉴切换实体种类后回到正面和第一张实体卡。时间轴收起后，展开按钮位于底部中央，复用收起样式。

## 数据与接口

`DataManager` 加载实体 JSON、V3 卡片和图谱索引；`GraphClient.resolve_entity` 先匹配稳定编号，再按唯一名称与类型匹配。地图 `FANG-*` 编号必须转换成 `TC-FANG-*` 后发送给 RAG。同名或缺失映射不自动猜测。

- `POST /api/v1/ai/game-chat`：复用现有后端 RAG，传入 `point_id` 和 `mode: knowledge`，检索图谱及资料后生成科普回答。
- `GET /api/v1/research/entities/{UUID}`：读取当前实体公开原文证据。
- 原邻域、路径、关系证据查询组件仍保留在代码中，当前第三页不展示拓扑与多跳查询控件。

本地 `config/llm_config.json` 已被 Git 忽略，不提交密钥。`rag_base_url`、`graph_base_url` 必须指向实际网关；当前开发机为 `http://127.0.0.1:18080`，其他机器按自身 Docker 映射配置。游戏鉴权使用后端 `GAME_API_KEY`；模型密钥由后端配置。Docker 后端属于相邻独立工程，本次 PR 不包含该工程文件。

## 数据同步与验证

- `tools/sync_far_scale_cards.py`：将原型数据同步到 `data/far_scale_cards.json`。
- `tools/export_graph_entity_index.py`：从完整实体 JSON 生成本地索引；UUID 规则为 `uuid5(NAMESPACE_URL, "tang-changan:entity:" + key)`，需与后端保持一致。
- `tools/test_far_scale_cards.gd`：远景数据及远中近景路由回归。
- `tools/test_entity_card_fields.gd`：坊与道路实体映射、字段、关联名称和原文单位。
- `tools/test_graph_contract.py <Godot控制台程序>`：临时本地模拟接口，覆盖图谱/路径接口、证据、错误与页面隔离，不调用付费模型。
- `tools/test_live_card_rag.gd`：需要已配置的本地后端与密钥；会实际调用模型，验证介绍及第二轮问题同步。

真实 RAG 已在开发阶段联调通过；提交前离线测试不能代替目标部署环境验收。部分 Godot 测试退出时仍有资源释放警告。
