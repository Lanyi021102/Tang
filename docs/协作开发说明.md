# 唐长安城项目 — 人员协作开发说明

> 本文档面向参与本项目的所有成员，说明**代码架构**、**各自负责的目录**、**改代码的具体操作**，以及**如何避免多人协作时的 Git 冲突**。

---

## 一、核心原则

1. **场景组件化**：UI、地图、数据、网络各自独立，通过接口/信号通信。
2. **逻辑事件驱动**：模块之间**不直接引用对方的节点路径**，统一走全局 `EventBus`（事件总线）信号。
3. **资源解耦**：所有本地数据（JSON）由 `DataManager` 统一加载；网络请求由 `NetworkManager` 统一封装。
4. **不碰别人的文件**：每个人只在自己的目录/文件里工作，避免同一文件被多人同时修改。

---

## 二、架构总览（Autoload 单例）

这些是全局单例（注册在 `project.godot` 的 `[autoload]` 段），**运行游戏时才会出现在场景树最顶端（Remote 视图）**，不在任何 `.tscn` 里。

| 单例 | 文件 | 职责 | 维护人 |
|------|------|------|--------|
| `EventBus` | `autoload/EventBus.gd` | 全局信号总线，模块间唯一的通信方式 | 主程 |
| `GameManager` | `autoload/GameManager.gd` | 全局状态（视角模式 / 年份 / 时间 / 图鉴进度） | 主程 |
| `DataManager` | `autoload/DataManager.gd` | 加载并缓存 `data/` 下所有 JSON | 图谱工程师 + 主程 |
| `NetworkManager` | `autoload/NetworkManager.gd` | 封装 LLM / 后端 HTTP 请求 | AI 后端工程师 |

### 事件通信示例

```gdscript
# 发起方（比如主程点击建筑后）
EventBus.building_selected.emit(building_id, data)

# 监听方（比如 UI 收到后展开卡片）
func _ready():
    EventBus.building_selected.connect(_on_building_selected)

func _on_building_selected(id, data):
    # 更新 UI，不直接访问地图节点
    pass
```

### 已有信号（`autoload/EventBus.gd`）

| 信号 | 触发时机 | 参数 |
|------|----------|------|
| `view_mode_changed` | 切换远景/中景/近景 | `mode: String`（"far"/"mid"/"near"）|
| `building_selected` | 点中建筑/坊 | `id, data` |
| `building_deselected` | 取消选中 | — |
| `npc_dialogue_started` | NPC 开始对话 | `group_id: int` |
| `time_of_day_changed` | 时间改变 | `hour: float` |
| `year_changed` | 年份跳转 | `year: int` |
| `codex_entry_collected` | 图鉴解锁新词条 | `category, keyword` |

## 四、具体操作流程

### 1. 开工前（每次都要做）

```bash
git checkout main
git pull
git checkout -b feature/你的功能
```

### 2. 改数据（图谱工程师/策划，零代码）

1. 编辑 `data/codex_kb.json` 等 JSON 文件（改词条、加关键词、改历史事件）。
2. 保存后直接跑游戏，`DataManager` 会自动加载新数据。
3. **不需要改任何 `.gd` 脚本**，不需要知道代码逻辑。

### 3. 改网络请求（AI 后端工程师）

1. 只编辑 `autoload/NetworkManager.gd`：
   - 想换接口 → 改 `request_chat()` 里的 URL / 请求体。
   - 想改解析逻辑 → 改 `_on_request_completed()`。
2. 游戏侧只依赖 `chat_response(content, error)` 信号，**你改内部实现，游戏逻辑不受影响**。

### 4. 改 UI（UI 设计师）

- 换按钮皮肤：直接替换 `assets/ui/*.png`（同名覆盖即可，零代码）。
- 加新 UI：在 `scenes/ui_overlay.gd` 里绘制；如需联动游戏，**连 `EventBus` 信号**，不要访问 `map._xxx` 私有变量。

### 5. 改主逻辑（主程）

- 只改 `scenes/changan_map.gd` 及相关 `.gd`。
- 新增跨模块事件：先在 `autoload/EventBus.gd` 声明信号，再在触发点 `emit`。

### 6. 提交并推送

```bash
git add -A
git commit -m "简述改动"
git push -u origin feature/你的功能
```

到 GitHub 发 **Pull Request**，至少 1 人批准后合并进 `main`。

---

## 五、避免冲突的关键约定

1. **`main` 受保护**，只能通过 PR 合并，不能直接 push。
2. **一个 `.tscn` 同时只有一个人改**；多人协作时，UI 加按钮、地图加节点前先沟通。
3. **别直接引用对方节点的路径**（如 `get_node("../HUD/BtnBack")` 要慎用），优先走 `EventBus` 信号或公开方法。
4. **保留 `.uid` 文件**：`*.gd.uid`、`*.tscn.uid` 提交时不要删，否则资源引用会断。
5. **密钥不入库**：`config/llm_config.json` 已被 `.gitignore` 忽略，只提交 `llm_config.json.example` 模板。
6. **数据先行**：后端接口/图谱数据没就绪前，`DataManager`、`NetworkManager` 先用本地 Mock 数据，前端照常开发。

## 六、快速排查

| 问题 | 原因 / 解决 |
|------|-------------|
| 找不到 EventBus 等单例节点 | 它们不在场景里，运行时切到 Scene 面板的 **Remote** 视图顶部才能看到；或在 Project → Project Settings → Globals 里查看 |
| 游戏提示未配置 API Key | `cp config/llm_config.json.example config/llm_config.json` 后填入自己的 Key |
| 改了 PNG 没生效 | 删除 `.godot/imported/` 里对应 `.ctex` 或让编辑器重新扫描 |
| 打开项目报兼容错误 | 确认用的是 Godot **4.7** 版本 |
